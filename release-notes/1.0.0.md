## oxfmt-quick@0.2.0

Changes the default mode to match `pretty-quick`.

### BREAKING CHANGES

**A bare `oxfmt-quick` no longer means `--staged`.** It now formats everything changed
since the merge-base with `--branch`, plus untracked files — which is what a bare
`pretty-quick` does. Pre-commit mode is opt-in:

```diff
  # .husky/pre-commit
- pnpm exec oxfmt-quick
+ pnpm exec oxfmt-quick --staged
```

**Update your hook before upgrading.** The two modes differ in more than which files they
pick: the default mode deliberately does not re-stage, because re-staging only makes sense
for files already in the index. A hook left on the bare command would format your working
tree while the commit itself kept the unformatted content — it would appear to work, and
quietly stop gating.

`--no-staged` is gone, having nothing left to negate.

The reason for the change is that 0.1.0 inverted the default of the tool this one is
modelled on, which is precisely the kind of difference that is discovered the hard way.
Everything else about the two modes is unchanged.

### Changes

- `--staged` is now opt-in; the default is changed-since-merge-base plus untracked files.
- `--since <rev>` no longer needs to imply anything, since the default is already the
  revision-comparison mode.
- The CLI help and README lead with the default rather than with pre-commit mode.

### Packaging

No dependency, engine or export changes. `oxfmt` remains a peer dependency at `>=0.60.0`.
