## oxfmt-quick@1.0.0

First release. Runs [oxfmt](https://oxc.rs/docs/guide/usage/formatter) on the files a commit
actually contains, then re-stages them — what
[`pretty-quick`](https://github.com/prettier/pretty-quick) is to Prettier.

It exists because migrating a monorepo from Prettier to oxfmt
([soroush-tech/core#328](https://github.com/soroush-tech/core/issues/328)) left a hole:
`pretty-quick --staged` had no oxfmt equivalent, and the pre-commit hook was reduced to a
whole-repo `--check` that fails instead of fixing.

### Features

- **`--staged`, the default.** Formats the staged files and re-stages them, so an unformatted
  tree cannot land. Anything unstaged is not going into the commit, so it is left alone.
- **`--no-staged`, `--since <rev>`, `--branch <name>`.** Formats what changed since the
  merge-base, plus untracked files. The merge-base is used rather than the branch tip, so a
  branch that has fallen behind does not drag in unrelated files.
- **`--check`, `--bail`, `--no-restage`, `--config <path>`, `--verbose`.**
- **A library, not just a CLI.** `oxfmtQuick(directory, options)` returns
  `{ success, errors }` and takes callbacks for every event; the CLI is a thin reporting layer
  over it. See the
  [README](https://github.com/soroush-tech/oxfmt-quick/blob/main/README.md#api).

### Partially staged files

A file that is staged and then edited again is formatted but deliberately **not** re-staged:
`git add` would sweep the unstaged edits into the commit and silently widen it. The run reports
`PARTIALLY_STAGED_FILE` and exits non-zero so the staging can be amended. This is a real bug in
at least one comparable tool ([biomejs/biome#3608](https://github.com/biomejs/biome/issues/3608)).

### Notes

- **No config or ignore handling of its own.** oxfmt already applies `.oxfmtrc`, `.gitignore`,
  `.prettierignore` and `.editorconfig`, and skips files it cannot format — so there is no
  second implementation here to drift out of step with it, and no extension filter.
- **oxfmt is asked for the changed set in one batch** via `--list-different`, rather than each
  file being read and compared in Node. `--list-different` exits 1 when it finds something,
  which is a report and not a failure, so the exit status is read rather than thrown on.
- **oxfmt is invoked through its own `bin` script with the current `node`**, not by looking
  `oxfmt` up on `PATH` — on Windows that entry is a `.CMD` shim which cannot be spawned without
  a shell, and a shell would reintroduce the quoting problems an argv array avoids.
- **Paths survive intact.** Files are collected with `git diff -z` and split on NUL, so spaces,
  non-ASCII characters and newlines are safe. `git add` is issued in batches of 100 so a large
  changeset cannot exceed the command-line length limit.

### Packaging

- Requires Node `^20.19.0 || ^22.12.0 || >=24`.
- `oxfmt` is a **peer dependency** (`>=0.60.0`) — consumers choose the version.
- Runtime dependencies are `mri` and `picocolors`. Nothing else.
- Ships ESM and CJS with types, from a `files: ["dist"]` allowlist, so `release-notes/` and
  `test/` are never part of the tarball.
